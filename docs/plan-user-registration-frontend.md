# Plan: User Registration Frontend

**PRD:** [docs/prd-user-registration.md](prd-user-registration.md)
**Дата:** 2026-08-23
**API Status:** `POST /auth/register` endpoint is implemented and ready at `http://localhost:3000/auth/register`

## Фазы реализации

### Фаза 1: Минимальная регистрационная форма (Tracer Bullet)

**Цель:** Создать рабочий путь: форма → валидация → отправка → получение токена
**Затрагивает:** Frontend (React)
**Задачи:**

- [ ] Создать компонент `RegistrationForm` с полями email и password
- [ ] Добавить локальное состояние для управления значениями полей (useState)
- [ ] Реализовать обработчик submit с POST запросом к `/auth/register`
- [ ] Сохранить полученный JWT токен в `localStorage` или состояние приложения
- [ ] Написать E2E тесты: регистрация с валидными данными → получение токена

**Когда готова:**

- Форма отправляет email и пароль на сервер
- Токен успешно получается и сохраняется
- Тесты подтверждают весь путь регистрации

---

### Фаза 2: Обработка ошибок и пользовательская обратная связь

**Цель:** Показать пользователю ошибки валидации и конфликты, обновить состояние приложения
**Затрагивает:** Frontend (React)
**Задачи:**

- [ ] Добавить обработку ошибок API (400 валидация, 409 дублирование email)
- [ ] Отобразить сообщения об ошибках рядом с соответствующими полями (inline validation messages)
- [ ] Отобразить глобальное сообщение об ошибке (снизу страницы или modal)
- [ ] После успешной регистрации обновить state приложения (текущий пользователь, аутентификация)
- [ ] Написать тесты: ошибка дублирования email, ошибка валидации пароля

**Когда готова:**

- Ошибки отображаются пользователю четко
- Приложение знает о залогиненном пользователе после регистрации
- Все сценарии ошибок покрыты тестами

### Фаза 3: Состояния загрузки и UX улучшения

**Цель:** Показать загрузку, предотвратить повторную отправку, улучшить доступность
**Затрагивает:** Frontend (React)
**Задачи:**

- [ ] Добавить состояние loading при отправке формы
- [ ] Отключить кнопку submit и поля ввода во время загрузки
- [ ] Показать spinner или текст "Регистрируемся..." во время запроса
- [ ] Добавить accessibility атрибуты (aria-label, aria-describedby для ошибок)
- [ ] Написать юнит-тесты: loading state, disabled кнопка

**Когда готова:**

- Форма не позволяет повторную отправку
- Пользователь видит, что форма обрабатывает запрос
- Форма доступна для скринридеров

### Фаза 4: Проверка предварительных условий и редирект

**Цель:** Перенаправить уже залогиненного пользователя и интегрировать с навигацией приложения
**Затрагивает:** Frontend (React, роутинг)
**Задачи:**

- [ ] Проверить, залогинен ли пользователь, перед показом страницы регистрации
- [ ] Если залогинен — редирект на главную или кабинет
- [ ] После успешной регистрации редирект на главную страницу или кабинет
- [ ] Написать тесты: редирект залогиненного пользователя, редирект после регистрации

**Когда готова:**

- Залогиненные пользователи не видят форму регистрации
- После регистрации пользователь попадает на нужную страницу
- Логика редиректа протестирована

## Зависимости и открытые вопросы

**Текущее состояние клиента:** Минимальный scaffold без routing, state management и API layer.

- **Routing:** Нужно настроить React Router. `/register` маршрут будет в новом файле `pages/Register.tsx`
- **State Management:** Нужно выбрать решение (Context API, Zustand, Redux) для хранения аутентификации
- **API Client:** Нужно создать utils для HTTP запросов (fetch wrapper или axios)
- **Styling:** Нужно выбрать подход (Tailwind CSS, CSS Modules, styled-components и т.д.)
- **Token хранение:** Рекомендуется localStorage (простой вариант для MVP) или Redux store
