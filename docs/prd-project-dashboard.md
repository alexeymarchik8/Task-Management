# PRD: Project Dashboard (Kanban Board)

**Дата**: 2026-08-24
**Статус**: Draft

## Цель

Дать участникам проекта общую доску задач, где видно, что в бэклоге, что в работе и что уже сделано, и можно завести/переместить/отредактировать задачу — без этого в проекте нет самого понятия "задача".

## Пользовательские сценарии

- Участник проекта открывает `/dashboard/:projectId` -> видит доску из 5 колонок: Backlog, To Do, In Progress, In Review, Done, в каждой — карточки задач проекта.
- Участник нажимает "Новая задача" -> заполняет заголовок (обязательно), описание, исполнителя, приоритет, срок -> карточка появляется в колонке Backlog.
- Участник перетаскивает карточку в другую колонку -> статус задачи меняется на статус этой колонки.
- Участник открывает карточку -> видит все поля и может отредактировать любое из них.
- Участник удаляет задачу -> карточка пропадает с доски.
- Пользователь, не являющийся участником проекта (ни owner, ни member), пытается открыть его доску -> получает отказ в доступе.
- Неавторизованный пользователь пытается открыть доску -> перенаправляется на страницу входа.

## В скоупе

- 5 фиксированных колонок-статусов: Backlog, To Do, In Progress, In Review, Done.
- Карточка задачи: заголовок, описание, статус, исполнитель (участник проекта), приоритет (low/medium/high), срок.
- Создание, редактирование, удаление задачи.
- Перенос задачи между колонками (смена статуса).
- Ограничение доступа к доске проекта только его участниками (owner/member).

## Не в скоупе

- Сайдбар и навигация между проектами — отдельная фича (`docs/prd-sidebar-navigation.md`).
- Аналитика/сводные метрики — отдельная фича (`docs/prd-home-analytics.md`).
- Комментарии к задаче, вложения, подзадачи, история изменений.
- Кастомизация набора/порядка колонок пользователем.
- Уведомления о назначении/смене статуса задачи.

## Технические ограничения

- Нужна новая модель данных `Task` (+ enum статусов и приоритетов) в Prisma — сейчас в схеме нет сущности задачи.
- Нужен новый backend-модуль с CRUD-эндпоинтами задач и проверкой, что текущий пользователь — участник проекта, к которому относится задача.
- Исполнителем задачи может быть только участник (`ProjectMember`) этого проекта.
- Доступ к странице и вызовы API требуют валидного JWT.

## Критерии готовности

- [ ] Участник проекта видит на `/dashboard/:projectId` 5 колонок с карточками задач этого проекта.
- [ ] Участник может создать задачу с заголовком, описанием, исполнителем, приоритетом и сроком.
- [ ] Новая задача появляется в колонке Backlog.
- [ ] Перенос карточки в другую колонку сохраняет новый статус задачи.
- [ ] Участник может открыть и отредактировать существующую задачу.
- [ ] Участник может удалить задачу, карточка пропадает с доски.
- [ ] Пользователь, не состоящий в проекте, не может получить данные его доски (нет доступа).
- [ ] Неавторизованный пользователь перенаправляется на login при попытке открыть доску.
