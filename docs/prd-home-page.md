# PRD: Home Page

**Дата**: 2026-08-23
**Статус**: Draft

## Цель

Дать залогиненному пользователю единую стартовую страницу, на которой видны его проекты и заявки на присоединение, и откуда он может создать проект или подать заявку на вход в чужой проект по коду.

## Пользовательские сценарии

- Пользователь открывает домашнюю страницу -> видит список "мои проекты" (проекты, где он owner или member).
- Пользователь нажимает "Создать проект" -> открывается форма создания, после успешного создания проект появляется в списке "мои проекты".
- Пользователь вводит код в форму "Присоединиться по коду" и отправляет -> заявка появляется во вкладке "мои заявки" со статусом pending.
- Пользователь переходит во вкладку "мои заявки" -> видит все свои заявки и их статусы (pending / approved / rejected).
- Пользователь, являющийся owner хотя бы одного проекта с pending-заявками, видит на странице in-app счётчик/бейдж количества таких заявок.
- Пользователь, являющийся owner, открывает список pending-заявок по своим проектам и видит для каждой заявки Approve/Reject.
- Неавторизованный пользователь пытается открыть домашнюю страницу -> перенаправляется на страницу входа.

## В скоупе

- Layout домашней страницы: список "мои проекты", кнопка "создать проект", форма "присоединиться по коду", вкладка "мои заявки".
- Отображение статусов заявок (pending / approved / rejected) во вкладке "мои заявки", включая возможность скрыть/удалить отклонённую заявку.
- Блок/секция pending-заявок по проектам пользователя (для случаев, когда он owner) с действиями Approve/Reject.
- In-app счётчик/бейдж непросмотренных pending-заявок для owner'а.
- Отображение сообщений об ошибках при создании проекта или подаче заявки (например, "заявка уже отправлена", "вы уже в проекте").
- Защита страницы: доступ только для авторизованных пользователей, редирект на login при отсутствии валидной сессии.

## Не в скоупе

- Бизнес-логика и API создания проекта, генерации кода, обработки заявок (Approve/Reject), уникальности — реализуются отдельными фичами/PRD, эта страница только их использует.
- Email/push-уведомления.
- Страница с деталями отдельного проекта (доски, задачи).
- Расширенная ролевая модель, управление участниками (кроме approve/reject заявки).
- Поиск и просмотр проектов без кода.

## Технические ограничения

- Страница зависит от готовых API-эндпоинтов для: списка проектов пользователя, создания проекта, подачи заявки, списка заявок пользователя, списка pending-заявок owner'а, approve/reject заявки.
- Доступ к странице и вызовы соответствующих API требуют валидного JWT.

## Критерии готовности

- [ ] Авторизованный пользователь видит на домашней странице список своих проектов.
- [ ] Пользователь может открыть форму создания проекта и увидеть новый проект в списке после успешного создания.
- [ ] Пользователь может ввести код и отправить заявку на присоединение через форму на странице.
- [ ] Вкладка "мои заявки" отображает все заявки пользователя с их актуальным статусом.
- [ ] Пользователь может скрыть/удалить отклонённую заявку во вкладке "мои заявки".
- [ ] Owner видит на странице счётчик/бейдж количества pending-заявок по своим проектам.
- [ ] Owner может увидеть список pending-заявок и выполнить Approve/Reject прямо со страницы.
- [ ] Ошибки создания проекта/подачи заявки отображаются пользователю понятным сообщением.
- [ ] Неавторизованный пользователь при переходе на домашнюю страницу перенаправляется на login.
