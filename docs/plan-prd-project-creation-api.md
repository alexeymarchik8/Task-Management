# Plan: Project Creation API

**PRD:** @docs/prd-project-creation-api.md
**Дата:** 2026-08-23

## Фазы реализации

### Фаза 1: JWT-middleware и защита роутов проекта

**Цель:** Дать серверу возможность определять текущего пользователя по токену и защищать роуты проекта от неавторизованных запросов.
**Затрагивает:** backend
**Задачи:**

- [x] Написать тесты на `verifyToken` middleware: валидный токен -> `req.userId` установлен, next() вызван; отсутствующий/невалидный токен -> 401.
- [x] Реализовать `verifyToken` middleware (`src/auth/verifyToken.ts`), переиспользуя логику проверки JWT из `src/auth/jwt.ts`.
- [x] Создать заглушечные роуты `POST /projects` и `GET /projects`, защищённые `verifyToken`, с тестом на то, что неавторизованный запрос к каждому возвращает ошибку авторизации.

**Когда готова:** Неавторизованный запрос на `POST /projects` и `GET /projects` возвращает ошибку авторизации; авторизованный запрос проходит middleware.

### Фаза 2: Модели Project и участия, генерация уникального кода

**Цель:** Подготовить хранение проектов и участников с гарантией уникальности кода.
**Затрагивает:** database, backend
**Задачи:**

- [x] Добавить в `prisma/schema.prisma` модель `Project` (id uuid, name, code уникальный 8 символов, ownerId, createdAt).
- [x] Добавить модель участия (например `ProjectMember`): userId, projectId, role (owner/member), связь с User и Project.
- [x] Прогнать `npx prisma migrate dev` для применения миграции.
- [x] Написать тесты и реализовать функцию генерации уникального 8-символьного кода (буквы+цифры) с повторной генерацией при коллизии в БД.

**Когда готова:** Миграция применена; функция генерации кода протестирована на уникальность (включая случай коллизии).

### Фаза 3: Эндпоинт создания проекта

**Цель:** Авторизованный пользователь может создать проект и стать его owner.
**Затрагивает:** backend
**Задачи:**

- [x] Написать тесты: создание проекта с названием -> 201 с id, name, code; отсутствие названия -> ошибка валидации, проект не создаётся; создатель становится единственным owner.
- [x] Реализовать `POST /projects` (`src/projects/createProject.ts`): валидация названия, генерация уникального кода, создание `Project` и записи участия с ролью owner в рамках транзакции.
- [x] Подключить роут в `src/app.ts` за middleware `verifyToken`.

**Когда готова:** Авторизованный POST-запрос с названием создаёт проект с уникальным кодом и ровно одним owner; запрос без названия возвращает ошибку валидации без создания проекта.

### Фаза 4: Эндпоинт списка проектов пользователя

**Цель:** Авторизованный пользователь получает список своих проектов (owner или member).
**Затрагивает:** backend
**Задачи:**

- [x] Написать тесты: пользователь получает только проекты, где он owner или member; пользователь без проектов получает пустой список.
- [x] Реализовать `GET /projects` (`src/projects/getProjects.ts`): выборка проектов через связь участия по `req.userId`.
- [x] Подключить роут в `src/app.ts` за middleware `verifyToken`.
- [x] Обновить `apps/server/CLAUDE.md` (и корневой `CLAUDE.md` при необходимости) описанием новых моделей и эндпоинтов проекта.

**Когда готова:** Авторизованный GET-запрос возвращает список проектов текущего пользователя (owner или member), корректно отражая изменения из Фазы 3.
