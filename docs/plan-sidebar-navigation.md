# Plan: Sidebar Navigation

**PRD:** docs/prd-sidebar-navigation.md
**Дата:** 2026-08-24

## Фазы реализации

### Фаза 1: Layout + список проектов в сайдбаре

**Цель:** Минимальный рабочий путь — на защищённых страницах появляется общий сайдбар со списком проектов пользователя.
**Затрагивает:** frontend
**Задачи:**

- [x] Тест: сайдбар рендерит список проектов пользователя, полученный из `GET /projects`.
- [x] Тест: сайдбар недоступен/не рендерится для неавторизованного пользователя.
- [x] `components/AppLayout` (сайдбар + `Outlet`) как общий layout для защищённых страниц.
- [x] `api/projectsApi.ts` — `listProjects`.
- [x] `components/Sidebar` + `components/Sidebar/components/ProjectList`.

**Когда готова:** Тесты фазы проходят; на защищённых страницах виден сайдбар со списком проектов пользователя.

### Фаза 2: Поиск, создание проекта, вступление по коду

**Цель:** Пользователь управляет своими проектами прямо из сайдбара.
**Затрагивает:** frontend
**Задачи:**

- [ ] Тест: ввод текста в поиск фильтрует список проектов по названию.
- [ ] Тест: успешное создание проекта добавляет его в список без перезагрузки страницы.
- [ ] Тест: отправка кода создаёт заявку и корректно отображает ошибки ("вы уже в проекте", "заявка уже отправлена").
- [ ] `components/Sidebar/components/ProjectSearch` (клиентская фильтрация списка).
- [ ] Формы "Создать проект" и "Присоединиться по коду" в сайдбаре (используют существующие `POST /projects`, `POST /projects/join`).

**Когда готова:** Тесты фазы проходят; можно искать, создавать проект и подавать заявку на вступление прямо из сайдбара.

### Фаза 3: Мои заявки и pending-заявки владельца

**Цель:** Весь жизненный цикл заявок на вступление управляется из сайдбара.
**Затрагивает:** frontend
**Задачи:**

- [ ] Тест: раздел "мои заявки" показывает все заявки пользователя с актуальным статусом.
- [ ] Тест: отклонённую заявку можно скрыть/удалить.
- [ ] Тест: owner видит счётчик pending-заявок по своим проектам и может Approve/Reject.
- [ ] API-клиенты для `GET /join-requests`, `DELETE /join-requests/:id`, `GET /join-requests/pending(+/count)`, `POST /join-requests/:id/approve|reject`.
- [ ] Раздел "Мои заявки" + блок pending-заявок владельца с бейджем в сайдбаре.

**Когда готова:** Тесты фазы проходят; пользователь видит статусы своих заявок и может их скрывать, а owner — рассматривать чужие.

### Фаза 4: Эндпоинт участников проекта

**Цель:** У бэкенда появляется способ отдать список участников конкретного проекта.
**Затрагивает:** backend
**Задачи:**

- [ ] Тест: `GET /projects/:id/members` для участника проекта возвращает список участников с email и ролью.
- [ ] Тест: пользователь, не состоящий в проекте, получает отказ в доступе.
- [ ] Добавить `GET /projects/:id/members` в `modules/projects` (repository + controller + route), защищённый проверкой членства.

**Когда готова:** Тесты фазы проходят; эндпоинт отдаёт участников проекта только его участникам.

### Фаза 5: Блок "Люди" и кнопка "Информация"

**Цель:** При открытом проекте в сайдбаре видно его участников и базовую информацию о нём.
**Затрагивает:** frontend
**Задачи:**

- [ ] Тест: на `/dashboard/:projectId` блок "Люди" показывает участников этого проекта.
- [ ] Тест: на Home (без открытого проекта) блок "Люди" отображается пустым/неактивным без ошибок.
- [ ] Тест: кнопка "Информация" открывает панель с названием, кодом и ролью пользователя для текущего проекта.
- [ ] `components/Sidebar/components/People` (подгружает участников при наличии активного `projectId` из роута).
- [ ] `components/Sidebar/components/InfoButton` + панель информации о проекте.

**Когда готова:** Тесты фазы проходят; при открытом проекте видно участников и информацию о нём, вне проекта — блок пуст без ошибок. Все критерии готовности PRD выполнены.
