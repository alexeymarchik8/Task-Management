# PRD: User Login

**Дата**: 2026-08-23
**Статус**: Draft

## Цель

Реализовать вход существующего пользователя по email и паролю: проверить учётные данные против БД и вернуть JWT-токен без создания новой записи пользователя.

## Пользовательские сценарии

- Пользователь отправляет email и пароль на эндпоинт логина -> учётные данные проверяются против БД, в ответе возвращается JWT-токен.
- Пользователь отправляет email, которого нет в БД -> получает ошибку авторизации, JWT не выдаётся.
- Пользователь отправляет существующий email, но неверный пароль -> получает ошибку авторизации, JWT не выдаётся.

## В скоупе

- Эндпоинт `POST /auth/login`, принимающий `email` и `password`.
- Поиск пользователя по email в PostgreSQL через Prisma.
- Сверка переданного пароля с хешем пароля в БД.
- Генерация и возврат JWT-токена при успешной проверке.
- Единая ошибка авторизации для случаев "email не найден" и "неверный пароль" (без указания, какой из них не совпал).

## Не в скоупе

- Регистрация нового пользователя (отдельная фича).
- Создание или изменение записи пользователя в БД в рамках логина.
- Refresh-токены и логика их обновления.
- Восстановление/сброс пароля.
- OAuth / вход через сторонние провайдеры.
- Rate limiting / защита от брутфорса на уровне этой итерации.

## Технические ограничения

- Логин работает только с пользователями, уже созданными через регистрацию (модель пользователя в Prisma должна уже существовать).
- Сравнение пароля выполняется через хеш-функцию, совпадающую с той, что использовалась при регистрации (bcrypt/argon2), пароль в открытом виде нигде не сравнивается напрямую.
- JWT должен подписываться тем же секретом из переменных окружения сервера, что используется при регистрации.

## Критерии готовности

- [ ] `POST /auth/login` с верными email/паролем возвращает JWT-токен и не создаёт новую запись пользователя в БД.
- [ ] Логин с несуществующим email возвращает ошибку авторизации.
- [ ] Логин с существующим email и неверным паролем возвращает ошибку авторизации.
- [ ] Возвращаемый JWT-токен корректно подписан и содержит идентификатор пользователя, соответствующего переданному email.
