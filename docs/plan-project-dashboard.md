# Plan: Project Dashboard (Kanban Board)

**PRD:** docs/prd-project-dashboard.md
**Дата:** 2026-08-24

## Фазы реализации

### Фаза 1: Данные + создание/список задач проекта

**Цель:** Минимальный рабочий путь — в проекте появляется сущность "задача", можно создать задачу и получить список задач проекта через API.
**Затрагивает:** backend, database
**Задачи:**

- [x] Тест: `GET /projects/:projectId/tasks` для участника проекта возвращает пустой список для нового проекта.
- [x] Тест: `POST /projects/:projectId/tasks` с валидным `title` создаёт задачу со статусом `backlog` по умолчанию и возвращает 201.
- [x] Добавить модель `Task` (+ enum `TaskStatus`, `TaskPriority`) в `prisma/schema.prisma`, миграция.
- [x] Создать `modules/tasks/` (routes/controller/repository/types) с `POST` и `GET` списка задач проекта.
- [x] Подключить роуты в `app.ts`, защитить `verifyToken` + проверкой членства пользователя в проекте.

**Когда готова:** Тесты фазы проходят; через API можно создать задачу в проекте и получить список задач этого проекта.

### Фаза 2: Обновление, удаление, перенос между статусами

**Цель:** Полный CRUD задач с проверкой доступа только для участников проекта.
**Затрагивает:** backend
**Задачи:**

- [x] Тест: `PATCH /tasks/:id` меняет статус задачи (перенос между колонками).
- [x] Тест: `PATCH /tasks/:id` меняет остальные поля (описание, исполнитель, приоритет, срок).
- [x] Тест: `DELETE /tasks/:id` удаляет задачу, повторный `GET` списка её не возвращает.
- [x] Тест: пользователь, не состоящий в проекте, получает отказ в доступе на всех task-эндпоинтах.
- [x] Реализовать `PATCH`/`DELETE /tasks/:id` в `modules/tasks` с проверкой членства через `projectId` задачи.

**Когда готова:** Тесты фазы проходят; полный CRUD задач работает через API с проверкой доступа.

### Фаза 3: Доска — колонки и карточки

**Цель:** Участник проекта видит доску с 5 колонками и реальными задачами проекта.
**Затрагивает:** frontend
**Задачи:**

- [x] Тест: рендер 5 колонок (Backlog/To Do/In Progress/In Review/Done) с карточками, полученными из API.
- [x] Тест: неавторизованный пользователь на `/dashboard/:projectId` перенаправляется на `/login`.
- [x] `api/tasksApi.ts` — `listTasks`, `createTask`, `updateTask`, `deleteTask`.
- [x] `pages/Dashboard` (проект берётся из `useParams().projectId`) + `components/KanbanBoard` с `Column`/`TaskCard`.
- [x] Группировка задач по статусу на 5 колонок.

**Когда готова:** Тесты фазы проходят; открыв `/dashboard/:projectId`, видно доску с реальными задачами проекта.

### Фаза 4: Создание, редактирование, перенос и удаление задачи с доски

**Цель:** Пользователь управляет задачами прямо с доски, не выходя из неё.
**Затрагивает:** frontend
**Задачи:**

- [ ] Тест: заполнение формы создания задачи приводит к появлению карточки в колонке Backlog.
- [ ] Тест: смена статуса задачи на доске отражается вызовом API и положением карточки.
- [ ] Тест: удаление задачи убирает карточку с доски.
- [ ] `components/TaskForm` (создание/редактирование) подключён к `pages/Dashboard`.
- [ ] Действие переноса карточки между колонками с вызовом `updateTask`.

**Когда готова:** Тесты фазы проходят; пользователь может создать, отредактировать, перенести между колонками и удалить задачу прямо на доске — все критерии готовности PRD выполнены.
