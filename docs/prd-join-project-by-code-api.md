# PRD: Join Project by Code API

**Дата**: 2026-08-23
**Статус**: Draft

## Цель

Дать авторизованному пользователю возможность подать заявку на присоединение к существующему проекту по его коду и отслеживать статус своих заявок.

## Пользовательские сценарии

- Авторизованный пользователь отправляет код проекта -> создаётся заявка (JoinRequest) со статусом pending, привязанная к пользователю и проекту.
- Пользователь повторно отправляет код проекта, по которому у него уже есть pending-заявка -> получает ошибку "заявка уже отправлена", дубликат не создаётся.
- Пользователь отправляет код проекта, в котором уже состоит (owner или member) -> получает ошибку "вы уже в проекте", заявка не создаётся.
- Пользователь отправляет несуществующий код -> получает ошибку "проект не найден".
- Пользователь запрашивает список своих заявок -> получает все заявки со статусами (pending / approved / rejected).
- Пользователь удаляет/скрывает свою заявку в статусе rejected -> заявка больше не возвращается в списке.

## В скоупе

- Модель `JoinRequest` (Prisma): id (uuid), userId, projectId, status (pending/approved/rejected), createdAt.
- Эндпоинт подачи заявки по коду проекта.
- Эндпоинт получения списка заявок текущего пользователя.
- Эндпоинт удаления/скрытия заявки в статусе rejected текущим пользователем.
- Валидации: запрет дублирующей pending-заявки от одного пользователя на один проект; запрет заявки от уже состоящего в проекте пользователя; проверка существования проекта по коду.

## Не в скоупе

- Создание проектов (отдельный PRD).
- Approve/Reject заявок владельцем и списки pending-заявок для owner (отдельный PRD).
- UI/страницы — только API.
- Уведомления любого типа.

## Технические ограничения

- Эндпоинты защищены JWT (используется middleware из Project Creation API).
- JoinRequest уникальна по паре (user, project) в статусе pending — обеспечивается на уровне БД или бизнес-логики.
- Идентификаторы — UUID.

## Критерии готовности

- [ ] Авторизованный пользователь может подать заявку по валидному коду проекта, заявка создаётся со статусом pending.
- [ ] Повторная заявка при существующей pending-заявке по тому же проекту возвращает ошибку и не создаёт дубликат.
- [ ] Заявка от пользователя, уже состоящего в проекте, возвращает ошибку и не создаётся.
- [ ] Заявка по несуществующему коду возвращает ошибку "проект не найден".
- [ ] Пользователь может получить список всех своих заявок с актуальными статусами.
- [ ] Пользователь может удалить/скрыть свою заявку в статусе rejected, после чего она не возвращается в списке.
