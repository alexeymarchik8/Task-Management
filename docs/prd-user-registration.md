# PRD: User Registration

**Дата**: 2026-08-23
**Статус**: Draft

## Цель

Реализовать регистрацию нового пользователя по email и паролю: создать запись пользователя в БД и вернуть JWT-токен для немедленной авторизации.

## Пользовательские сценарии

- Пользователь отправляет email и пароль на эндпоинт регистрации -> создаётся запись пользователя в БД, в ответе возвращается JWT-токен.
- Пользователь пытается зарегистрироваться с email, который уже есть в БД -> получает ошибку с указанием, что email уже занят, пользователь не создаётся.
- Пользователь отправляет невалидный email или слишком короткий пароль -> получает ошибку валидации, пользователь не создаётся.

## В скоупе

- Эндпоинт `POST /auth/register`, принимающий `email` и `password`.
- Валидация формата email и минимальной длины пароля.
- Проверка уникальности email перед созданием пользователя.
- Хеширование пароля (bcrypt/argon2) перед сохранением — пароль в открытом виде не хранится.
- Создание записи пользователя в PostgreSQL через Prisma.
- Генерация и возврат JWT-токена в ответе на успешную регистрацию.

## Не в скоупе

- Вход в систему (login) по уже существующим учётным данным.
- Подтверждение email (email verification).
- Восстановление/сброс пароля.
- Refresh-токены и логика их обновления.
- OAuth / вход через сторонние провайдеры.
- Rate limiting / защита от брутфорса на уровне этой итерации.

## Технические ограничения

- Хранение пользователей — PostgreSQL через Prisma; для эндпоинта требуется миграция схемы Prisma с моделью пользователя (email, password hash).
- Пароль обязан храниться только в виде хеша, не в открытом виде.
- JWT должен подписываться секретом из переменных окружения сервера.

## Критерии готовности

- [ ] `POST /auth/register` с валидными email/паролем создаёт пользователя в БД и возвращает JWT-токен в ответе.
- [ ] Пароль в БД хранится в виде хеша, а не в открытом виде.
- [ ] Повторная регистрация с уже существующим email возвращает ошибку и не создаёт вторую запись.
- [ ] Регистрация с невалидным email или паролем короче минимальной длины возвращает ошибку валидации и не создаёт пользователя.
- [ ] Возвращаемый JWT-токен корректно подписан и содержит идентификатор созданного пользователя.
